## 0. 摘要

投放区"成功率不高 / 正上方不投"的**直接原因是 2.8m→1.5m 最终下降是盲降**(goto_ned 无视觉反馈,下降期间像素伺服完全不运行)。盲降漂移(按 fx=400 口径到达 1.5m 时偏差 **39cm / 61cm**)破坏对心后,1.5m 低空重对心在 FPS 3-5 下结构性失败:**不是帧率**。v1 的帧率优先排序有误。

**最优方案:把最终下降改为"伺服下降"**(下降全程水平像素修正 + 垂直 0.25m/s,test_mission 已验证模式),帧率优化(X1)降级为配套。**确认论证见 §1.4 对比表。**

## 1. v1 → v2 根因修正(为什么 v2 更好)

### 1.1 v1 根因回顾(已证伪部分)

v1 根因 #1: 两模型串行推理 → 精校 FPS 3-5 → 伺服追过时误差振荡。方案 X1 优先提帧率。

### 1.2 日志回放证据:帧率不是主凶

**证据 E1 — 2.8m 对心在低帧率下同样快速收敛:**

| 轮次 | 时段 | 像素误差过程 | 结论 |
|---|---|---|---|
| 投放#1 @2.8m | T+1809→1822(13s) | 77→79→86→80→91→100→95→82→73→62→41→21.6px **单调递减** | 收敛正常 |
| 投放#2 @2.8m | T+1874→1884(10s) | 132→148→131→135→116→82→71→48→40→65→23.9px | 收敛正常 |
| retry 后 @1.5m | T+1932→1934(2s) | 101.8→64.5→11.0px | **重置后 2s 即收敛** |

> 4 次对心全部在 FPS 3-12 下成功 — 低 FPS 本身不阻塞收敛。

**证据 E2 — 许可失败日志分布:大头在 1.5m 盲降之后(76 条 1Hz 节流日志,53 条在 1.5m):**

| 阶段 | 日志条数 | 性质 |

**证据 E3 — 盲降到达时刻的像素误差(盲降破坏对心的直接证据,按 fx=400 口径):**

- 投放#1:T+1822.8 在 2.8m 已 `允许投放 raw=11.6px stable=5/4`,随后进入最终下降;T+1830.6 到达 1.5m,**pixel_error=104.9px ≈ 39cm**

**证据 E4 — retry 机制证明振荡放大器是 EMA/锁定状态:**

T+1931.9 低空精校超时 → `_retry_precision_align_in_place`(`reset()` 清 EMA + 重新锁目标)→ **2s 内收敛并投放**。同样的 1.5m、同样的 FPS,重置前 41s 不收敛,重置后 2s 收敛 → 滞后 EMA(alpha=0.55@333ms/帧,响应滞后 ~1s)+ 每帧漂移的目标锁定构成振荡正反馈。

**证据 E5 — 帧率事实**:2.8m 段 FPS 5-6、1.5m 段 3-5(398ms)、5m 高空 8-12。帧率确实差,但不是"对心失败"的充分条件(E1)。

| — | 两模型串行推理 FPS 3-5 | E5 | **#1(降级为放大器)** |

### 1.4 确认:为什么 A1(伺服下降)优于 v1 的 X1(帧率优先)

| 维度 | X1 单模型推理(v1 首选) | A1 伺服下降(v2 首选) |
|---|---|---|
| 作用机制 | FPS 3-5→~6,缩小观测滞后 | **消除盲降,对心在下降全程保持**(到达 1.5m 时预计 <30px) |
| 是否触及 R1 | 否(盲降依旧,到达仍偏 100px+,只恢复快一倍) | **是(R1 直接消除)** |
| 是否触及 R2/R3 | 部分(恢复快;门禁依然清零) | 是(不再需要 1.5m 重对心,许可自然通过) |
| 是否触及 R4(落点) | 否 | 是(39-61cm 漂移 → <11cm 窗口内) |
| 对 H 降落 | 无帮助(landing 模式已单模型 17FPS,仍失败) | 无帮助(需 B1-B3,另列) |
| 风险 | 低 | 中(低空伺服依赖检测连续性;丢失期间悬停重捕获兜底) |
| 成本 | 中(pipeline 模式重构) | 中(controller +40-60 行) |
| 可回退 | 是 | 是(一行配置 `final_descent_enable=false` 回退 2.8m 直接投) |
| 叠加性 | 可叠加(A1 之后提升复查速度) | 可叠加 |

**结论:** X1 只放大"带宽",A1 直接消除根因,且不依赖 FPS 提升即可生效(2.8m 段 FPS 5-6 已能收敛,下降全程保持在 2.8m 水平的修正即可)。A1 有配置级回退路径。**A1 必须先于 X1 实施,这是与 v1 的根本差异。**

## 3. 方案(更新后,按优先级)

### P0 投放区:伺服下降重构(最高优先级)

#### A1(新) 最终下降伺服化

- **目标行为**:2.8m 对心锁目标后,不再 goto_ned 盲降;每 tick 输出 `set_velocity_body(水平像素修正, -0.25)`,垂直下降恒开、水平由像素伺服控制,直到高度到位 → 停垂直 → 现有复查(刹车/稳定帧/像素复查)→ 投放。与 test_mission 降落段同一模式。
- **实现点**:
  - `precision_align_controller.py`: `step()` 增加 `descent_speed: float = 0.0` 参数;`set_velocity_body(fwd, right, 0.0)` 改为 `(fwd, right, descent_speed)`;hover/brake 段垂直不停;最终下降阶段 `stop_velocity()` 改为 `set_velocity_body(0, 0, descent_speed)`
  - `state_drop.py`: `_start_final_descent_if_needed()` 不再发 goto_ned,改置标志;`_execute_descend` 最终下降分支每 tick 调 `_nudge_to_visible_drop_target(drop_h, descent_speed=-0.25)`;高度到位复用 `_check_descent_ready`(stall 检测,快速通道已禁用)
  - 参数复用:`precision_align_final_descent_speed`(0.25)、`precision_align_final_drop_height`(1.5)、`precision_align_final_brake_s`(0.5)
- **目标丢失处理(沿用现有机制)**:下降中丢失 → 悬停重捕获(`reacquire_after_lost=12` 帧)→ 超限走现有 retry(E4:重置后 2s 收敛)→ retry 耗尽接管。丢失期间垂直暂停优于盲降。
- **预期效果**(对 E2 定量):许可失败日志 76→<10 条;单次投放 DESCEND 耗时 39s/66s → <20s;1.5m 到达像素误差 105/163px → <30px(≈11.3cm 窗口内)。
- **风险与回退**:低空检测连续性差 → 下降中反复丢失 → 回退 `precision_align_final_descent_enable: false`(2.8m 对心即投,窗口 35px≈24.5cm,精度下降但任务可完成)。

#### A2 投放许可容错(一行级)

- 稳定帧 4 连 → "最近 5 帧 ≥3 帧通过"(滑动窗口),或 4→3。低 FPS 下单帧超标清零是 R3 一部分,与 A1 配套。
- 注意与 Z5 联动:若现场标定后 `final_raw_pixel_tolerance` 收紧(如 30px→13px@1.5m 换 5cm 窗口),稳定帧要求应保持宽松(A2),避免双重收紧。
