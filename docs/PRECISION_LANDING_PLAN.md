## 4. 明确**不做**（附理由，防止后人重开）

| 事项 | 理由 |
|---|---|
| 用估计器速度做阻尼/前馈 | 正典对静止目标有明文结论：`∂e/∂t = 0` 时"用最简单的估计 `∂e/∂t̂ = 0` 即可"。本项目被估计量是目标**世界位置**，静止降落垫下其速度状态本就≈0；被误检污染时是沿 NED 的伪指令 |
| 恢复 `kd`（对原始误差的 D 项） | 正典控制律中不存在对原始误差的 D 项；导数只作为"被滤波的目标运动估计"以**前馈**注入 |
| S8 终端兜底（悬停 N 秒后自主降落） | 与本项目**被测试钉住**的策略冲突：`request_takeover` 之后只零速度悬停交飞手，**绝不自主 RTL/降落**（`test_operator_takeover_contract.py`） |
| S5 的"未对准保持高度"那一半 | 单独上会让持续偏心的目标永不下降 → 悬停 → 超时接管，把 8/14 的"卡住"放大 |
| S1 驻留改测量键控 | quick 真机档的 1 帧阈值是**针对真机观察到的"10 帧锁存常不达成"刻意放宽的**，改严会让近地更容易悬停等待 → 更容易异地降落。要改必须先有配套兜底 |
| 用 50Hz 姿态差分替代角速度 | 姿态流带宽看不到 80Hz 振动，而 A2 存在的意义正是振动/机动降权 → 会给虚假的覆盖感 |
| **把台面仿真的量化数字当作决策依据** | 一次独立对抗审计（3 个视角 + 综合）判定：该工具**可以**作为"控制律直觉"与"发现自相矛盾"的探针，**不可以**作为"某个改动能降多少偏差"的证据。已核实的三处失真：<br>① **时钟假象（最严重）**：状态里的估计器 `predict` 与丢线复位用 `time.monotonic()`，而台面仿真比实时快约 **1760 倍**（实测 12 s 仿真时间只花 0.0068 s 墙钟）→ 滤波器 dt≈2e-5 s、过程噪声不增长、门不随仿真时间演化。**"门降低 70–90%" 由此而来，接对仿真时钟后降为 0 甚至变差**（已写入 §3 U1）。<br>② **不走 FSM 分发层**：仿真直接调 `_execute_servo()`，从不调 `execute()`，于是真机对检测间隙的全部处置被静默移除——尤其 **quick 真机档丢失 1.0 s 即 `_request_px4_land()` 放弃精准降落**。<br>③ **失效模型与真机不同**：仿真把"检测失效"建模成"旧目标一直有效"，而真机 miss 帧仍会到达（`confidence=0.0`）并被置信度门（0.60）在**下一帧**判为 None —— 所以真机根本不会"靠下降穿过失效带"。<br>因此本工具的定位收缩为：**抓自身的自相矛盾 + 定性探针**，其数字一律不进决策。 |
| **重试阶梯（爬升 ~1.5m 再降回）** | **2026-10-13 用户否决**：本项目控制核心是"对心连续伺服、**持续靠近目标**"——丢失或被拒不中断逼近。权威 ArduPilot 的 `+1.5m` 爬升重试属于"丢失后重建观测几何"的另一套哲学（`AC_PrecLand_StateMachine.cpp:150-235`），与"不中断逼近"不相容，故不采用。代价要写明：对"检测在某高度带整体失效"这类失败，原地逼近无法产生新观测几何——但那条失效模式已由 2026-08-15 的 B1+A 从**检测侧**处理（放宽 refine 门槛 + 用历史最佳对心证据兜底投放），不依赖重试几何。 |
| **被拒帧的零速保持** | **同上原则的直接推论**：我原本让卡方门拒绝时零速悬停，与紧邻的"目标丢失"分支（继续飞向最后已知位置）自相矛盾。已改为**与"没有可用测量"完全同一处置**：不据此下令，但继续前进。 |
| **往台面仿真里加"检测失效带"场景** | 三条理由，其中第一条是**对一次错误结论的撤回**：<br>① **接错了子系统**——我把场景接在**降落状态**（`state_precision_land_*`）上，而失败记录里"卡投放区"发生在**投放精校**（`precision_align_controller` + `state_drop`），是不同代码路径；因此由它得出的"检测失效带无害"**不成立，已撤回**。<br>② **要建模的失效已经修好**：该模式已于 2026-08-15 由 B1（下降段放宽 refine 门槛）+ A（跨 retry 跟踪最佳地面误差，≤0.4 m 直接投放）修复，且**已在本分支**（`state_drop.py:1177`、`mission_params_quick.yaml:126`）。给已修的问题建模是浪费。<br>③ **场景本身走不到被测分支**：四组配置里最多只有 4/467 个 tick 进入"目标视为丢失"分支，所以"四组数字相同"是场景无效的证据，不是"无害"的证据。已把这条自检写进工具——它现在**拒绝给出结论**并说明原因，而不是打印一张会被误读的表。 |

**顺带核实下来的失败机理**（此前只有猜测，现在有一手记录支撑）：8/14 的"卡住"是**自持循环**——
下降中丢检测（3.15–3.75 m，`no_candidates`）→ `stop_velocity()` 悬停 → **检测随即恢复**
（记录原文："悬停即恢复 (conf 0.96)"）→ 但仍达不到 `stable=3/3` → 重试耗尽 → `HOLD_FOR_TAKEOVER`。
即**悬停正是让检测回来的原因**，于是没有任何力量推动它改变策略。这也是为什么"继续下降"
或"用最佳历史对心证据兜底投放"是正确的修法方向（= 8/15 的 B1+A）。

- **时钟域**：全仓无 `use_sim_time`，ROS 时钟 == 系统时钟。这一巧合是当前一切时间戳比较
  成立的前提（一旦启用 sim time 或跨机器部署，现有的 `0 < stamp <= now` 会静默失效）。
- **给状态加"每 tick 都要调"的方法时**：`test_operator_takeover_contract.py` 用
  `object.__new__(MissionFSM)` 并直接调 `_control_loop_impl`，所以新增的每-tick 调用
  要么加进那个 double，要么放在**外层** `_control_loop`（重入防护之后）——本次选了后者，
  顺带也更正确（被跳过的 tick 不该采样）。
- **逐轴判据的陷阱**：图像 u 方向跳变只影响估计器的 east 轴，用 north 的
  `reject_streak` 判"本帧可否采信"会把误检放行。判据必须用**组合判决**
  （`last_observation_usable` / `last_observation_accepted`）。
- **写"扫代码找模式"的契约测试必须先做变异验证**：本次的参数契约测试写完第一次是
  **永远通过**的（`declare_parameter("x")` 的实参自己就是字面量，每个参数都
  "匹配到自己"）；修掉后又因**跨文件收集 AST 节点 `id()`** 而被 GC 复用，表现为
  每次运行报出不同的"未使用参数"。教训：注入一个已知违规，看它是否真的失败。
