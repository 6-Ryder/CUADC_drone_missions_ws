## 问题 4: 像素伺服方向符号错误

### 现象

```
APPROACH → World(43.63, 2.86), pixel_error=75px at 5m
DESCEND → 2m, pixel_error=212px
梯度下降: du 始终 +190~250px, dv 始终 -80~-200px
1s 后目标丢失, 放弃
```

### 根因

`x_sign=-1.0, y_sign=1.0` 两个方向都反了。仿真中 marker 在画面右侧(dv>0)时无人机需要向东移动，但 `x_sign=-1` 让 `dx = -1 × gain × du × alt/f` 算出的是西移。

### 修复

Commit `d9807f9`: 端到端像素空间梯度下降，不依赖 `x_sign/y_sign/fx/fy/gain` 硬编码参数。每个探测周期：
1. 记录基线 pixel_error
2. 探测 +step，采样
3. 探测 -step，采样
4. 三方比较，提交到最优端点

自适应步长: >200px→0.40m, >100→0.26m, >50→0.16m, ≤50→0.10m。

## 问题 5: 回锚点累计漂移

### 现象

```
baseline err=182px
+X probe err=212px (恶化) → 回锚点
回锚后 err=218px (锚点本身变了!)
-X probe err=199px vs baseline=182 → "恶化"
但实际上 vs 218 是改善了 19px
```

### 根因

探测模式 "+X → 回锚 → -X → 回锚 → 比较" 中，每次回到锚点时 pixel_error 因 YOLO 检测抖动/无人机微小漂移而变化，使比较基准不一致。

### 修复

Commit `a3597e5`: 端点比较法 — 不回锚点。+端点 → 直接跳到 -端点 → 三方比较(baseline/+/−)，选最优提交。探测步长基数从 0.20m 增大到 0.40m，SNR 从 ~1.8 提升到 ~3.5。

## 问题 6: 探测周期内 cylinder↔marker 身份切换

### 现象

```
baseline: src=cylinder  err=212px
+端点:    src=marker    err=374px  ← 不同目标!
-端点:    src=marker    err=267px
比较: baseline=212(cylinder) vs +=374(marker) vs -=267(marker)
→ "baseline最优" — 无意义的比较
```

### 根因

`_choose_target()` 每帧在 cylinder(检测不稳定) 和 marker(3个,始终可见) 之间切换。探测周期内采样到不同目标，方向判断随机。

### 修复

Commit `d35cb30`: baseline 时记录 `source`，± 端点采样时校验一致性。不一致 → 作废本轮回基线。

## 问题 7: 连续探针导致抽搐飞行

### 现象

```
X+飞 → 等1s → X-飞 → 等1s → 提交飞 → 等1s → 立刻Y+飞 → ...
6秒内收到4个互相矛盾的位置指令, 无人机从未真正悬停
```

第一次投放之所以成功了 1 次，是因为 COMMIT_AXIS 到位等待期间，无人机恰好经过了一个能让 pixel_error 降到 35px 以下的位置——巧合，不是设计。

### 修复

Commit `639bda0`: COMMIT_AXIS 到位后 → HOVER 悬停 2.5s → 再进入下一轴探测。悬停期间 `is_centered` 有机会累积稳定帧。

## 问题 8: 低空 cylinder 检测不稳定

### 现象

```
src=cylinder: 每 2~5 秒丢失一次, pixel_error=inf
src=marker:   始终可见, conf=0.95~0.98
```

每次 cylinder 丢失 → marker 顶上 → 身份切换 → 探测作废。即使加了身份校验，cylinder 的间歇性丢失导致有效探测周期极难完成。

### 修复

Commit `b55ee41`: 低空 (2m) `_current_targets()` 中 marker 优先、cylinder 兜底。marker 是画在圆筒下方地面上的蓝色圆形标识，对中 marker 中心 = 对中圆筒中心。

## 问题 9: marker 之间互相切换

### 现象

```
悬停中 pixel_error: 215 → 173 → 312 (无人机没动, 2.5s 内波动 140px)
```

### 根因

场上 3 个 marker (相距 1~3m)，在 2m 高度它们在画面中的位置不同。`_choose_target` 每一帧从 3 个 marker 中重新评分选最优，评分函数中 `world_error_to_memory` 随无人机移动而变化 → 相邻帧可能选中不同 marker → pixel_error 在完全不同的值之间跳。

### 修复

Commit `eea9562`: 第一次选中 marker 后锁定其 world 坐标 (`_locked_target_xy`)，后续只接受坐标在 2m 容差内的同一物理 marker。

## 问题 10: 算法过度复杂 (当前状态)

### 评估

梯度下降算法经历 5 轮迭代，当前实现包含：
- 6 个状态 (PROBE_X_PLUS/X_MINUS/Y_PLUS/Y_MINUS/COMMIT_AXIS/HOVER/BRAKING)
- 5 个时间窗口 (probe_settle/hover/brake_timeout/align_timeout/overall_timeout)
- 目标锁定、身份校验、自适应步长

每次仿真暴露一个新问题，修复后又暴露下一个。根本原因是**探测-比较-提交的离线模式与连续视觉伺服的在线需求不匹配**。

### 下一步方向

简化为两步：
1. **方向发现** (2s): ±X/±Y 小步探测，实测像素↔世界的方向映射
2. **连续伺服**: 每帧计算偏移 → 飞向目标 → 下一帧再算 → 再飞。pixel_error < 35px × 6帧 → 投放

回到第一版的公式 `dx = sign × gain × du × alt/f`，但 `sign` 不是配置文件写死的，是 2 秒前实测出来的。

### 关键发现

1. **marker 检测是稳定可靠的** (conf=0.95+, 始终 2-3 个可见) — 应用作主要伺服目标
2. **世界坐标粗定位偏差 ~1m 是固定的** (YOLO 坐标估计的系统误差)
3. **1m 偏差在 2m 高度对应 ~270px** — 在微调范围内 (理论收敛至 <100px)
4. **目标身份切换是所有失败场景的根源** — cylinder/marker/marker间 三级切换
5. **端点比较法的方向判断本身正确** (有一次成功投放证实)
