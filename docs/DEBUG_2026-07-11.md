## 问题 1: 圆筒 STL 网格俯视不可见 ✅

### 现象

```
CYL_SEARCH: 扫描完成但未累计到圆筒, 继续悬停等待
CYL_SEARCH: 超时, 使用当前检测结果
SELECT_TARGET: 搜索完成, 累计 0 个圆筒
→ 跳过投放流程, 直接去侦察区
```

投放区标识 (drop_marker) 检测正常 (3个, 置信度 95%)，圆筒检测为 0。

### 根因

`drone_field.sdf` 中的圆筒 visual 使用 STL 网格 (`cyl_r0075_h030.stl` 等)，该网格定义了开口杯形中空圆柱筒：

- **只有外壁表面** (576个三角面)，无顶面、无底面
- 外壁厚 5mm
- 从 5m 高度俯视：壁厚映射为 **0.5 像素**，低于奈奎斯特采样极限
- 蓝色 B 区底板透过空心露出，白环不可见
- YOLO 模型 (13px 白色圆盘可检测 @conf=0.726) 看不到目标

### 修复

修改 `PX4-Autopilot/Tools/simulation/gz/worlds/drone_field.sdf`，对投放区 3 个 + 侦察区 5 个圆筒 (共 8 个):

**B — 实体圆柱替代 STL 网格:**
```xml
<!-- 之前: 空心杯 STL 网格 -->
<mesh><uri>...cyl_r0075_h030.stl</uri></mesh>

<!-- 之后: 实体白色圆柱 -->
<cylinder><radius>0.0750</radius><length>0.3000</length></cylinder>
```

**C — 底部白色圆盘 (额外保障):**
```xml
<visual name="bottom_disk">
  <pose>0 0 -0.150 0 0 0</pose>
  <cylinder><radius>0.0750</radius><length>0.005</length></cylinder>
</visual>
```

### 验证结果

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 投放区标识 | 3个, 95% | 3-5个, 88-97% |
| 圆筒检测 | **0个** | **2/3个** |
| 任务流程 | 跳过投放 | 完成 2 轮投放循环 |

## 问题 2: CYL_COORD 姿态投影坐标异常 ⚠️

### 现象

```
[WARN] CYL_COORD: 姿态投影异常, 使用简化投影
  raw=(41.48,18.74) drone=(42.48,3.98)
  raw=(41.26,19.35) drone=(42.46,3.98)
  ...
```

`raw` 是 `CoordinateTransformer.pixel_to_world()` 的姿态补偿投影结果，`drone` 是无人机此刻的 World 坐标。

### 数据分析

| 指标 | 值 |
|------|-----|
| 偏差方向 | **Y 分量系统性偏大 ~14m** |
| X 分量 | 基本正确 (41-42m ≈ 圆柱实际 x=41.5-44m) |
| 过滤阈值 | max(drone_z*1.5, 3.0) ≈ 6-7m |
| 实际偏差 | 12-18m → 全部被 REJECT |

圆柱实际位置:
- cyl_1: world(41.5, 3.0)
- cyl_2: world(43.0, 5.5)
- cyl_3: world(44.0, 2.0)

姿态投影 raw_y=13-22m vs 实际 y=2-5.5m → **Y 分量错误指向北侧 14m 处**。

### 根因分析

`coordinate_transforms.py` 的 `pixel_to_world()` 方法 (第109-124行):

```python
R_cam_to_body = np.array([
    [0,  1,  0],   # 相机 y → body front
    [1,  0,  0],   # 相机 x → body right
    [0,  0, -1],   # 相机 z → body -down
])
ray_body = R_cam_to_body @ ray_cam

# PX4 四元数: body → NED (North-East-Down)
R_body_to_world = _quat_to_matrix(q)
ray_world = R_body_to_world @ ray_body

# 射线–地面求交, 结果当作 ENU 坐标使用
P_ground = P + t * ray_world
```

**坐标系不匹配:**

| 四元数输出 | World 实际 |
|------------|------------|
| NED x (north) | 被当作 World x (east) |
| NED y (east) | 被当作 World y (north) |
| NED z (down) | 被当作 World z (up) |

缺少 **NED→ENU 转换**。四个方案:

1. 在 `_quat_to_matrix(q)` 之后加 NED→ENU 变换矩阵
2. 修改 `R_cam_to_body` 补偿坐标系差异
3. 直接使用 `pixel_to_world_simple()` (简化版已正确: `world_x = drone_wx + (u-cx)*alt/fx`)
4. 在 PX4 bridge 中将 NED 位姿预转换为 ENU 后再发布

### 影响

- 姿态补偿投影的圆柱世界坐标 Y 分量偏大 ~14m
- 所有坐标被 `max_reasonable_offset` 检查拒绝 (代码第590-593行)
- 回退到 `pixel_to_world_simple()` 简化投影 (假设相机垂直向下)
- 简化投影在 drone 有 pitch/roll 时精度下降

## 问题 3: APPROACH 逼近阶段跟踪丢失 ⚠️

### 现象

```
APPROACH: 当前帧未见目标, 只使用记忆坐标粗靠近
  → (3.5s 后)
APPROACH: 到达记忆坐标但未重新看见目标, 放弃投放
  → ASCEND → 下一轮选择 (ID=2)
  → 同样 4.6s 后放弃 → TRANSIT_TO_RECON_ZONE
```

两次投放循环均以跟踪丢失告终。

### 根因

问题 2 导致的级联效应:

1. **CYL_SEARCH 阶段**: 圆柱在像素空间被 YOLO 检测到，但姿态补偿投影的 world 坐标被 REJECT，回退到简化投影
2. **简化投影假设相机垂直向下**，但 SCAN 扫描和 APPROACH 逼近时 drone 有 pitch/roll，产生位置偏差
3. **FSM 用错误的 world 坐标设置 `_target_world_xy`**，`_goto_target_xy()` 飞到错误位置
4. **飞到错误位置后圆柱不在视野中**，`_find_nearest_cylinder()` 返回 None
5. **进入记忆坐标粗靠近模式** (`_goto_target_xy`)，但目标坐标本身就有偏差
6. `_memory_arrival_count >= 20` 触发放弃

关键代码路径: `state_cylinder_approach.py`

```python
# Line 135-158
def execute(self):
    cylinders = self._fsm.get_cylinders()
    target_cyl = self._find_nearest_cylinder(cylinders)
    # _find_nearest_cylinder 使用 center_x, center_y (World坐标) 匹配
    # 偏差 >2m → 匹配失败 → 进入记忆坐标模式 → 最终放弃
```

### 修复方向

修复问题 2 (NED→ENU 坐标系转换) 是根本解决方案。此外:

- **防御性改进**: `_find_nearest_cylinder` 的 2m 匹配阈值在坐标偏差时过于严格
- **像素级匹配回退**: 当 world 坐标匹配失败时，可回退到纯像素伺服 (`_goto_pixel_centered_target`)，不依赖 world 坐标

```
修复前:
  TAKEOFF → TRANSIT → CYL_SEARCH(超时, 0个) → RECON → ...

  TAKEOFF → TRANSIT → CYL_SEARCH(2个) → SELECT ID=1

  TAKEOFF → TRANSIT → CYL_SEARCH(2-3个) → SELECT
    → APPROACH(对心) → DESCEND → DROP
    → ASCEND → SELECT → APPROACH → DESCEND → DROP
    → ASCEND → RECON → ...
       ↑ 两次成功投放
```
