# 全流程真机任务完善设计

日期：2026-08-04  
状态：已确认设计

## 1. 背景与当前基线

当前完整 SITL 已完成两次投放、侦察区完整覆盖、返航和 H 标识精准降落，任务摘要为成功。真机目前只验证了独立 `test_mission` 的前飞、侦察、返航和 H 降落链路；完整任务的圆筒搜索、两次投放以及投放后转场尚未完成真机闭环验证。

仓库已经具备完整任务所需的 PX4 DDS、相机、视觉、舵机和任务 FSM，但仍存在以下影响真机成功率的问题：

- 相机驱动、视觉管线和任务控制器使用了不同的参数名称与内参来源；
- `test_mission` 多处在超时后强制推进状态、跳过航点或自动 LAND/RTL；
- 主 FSM 的错误完成路径会停止任务定时器，但不会同步停止 `StandaloneBridge` 的周期设定点；
- 飞行中看门狗尚未形成阶段相关的恢复和等待接管行为；
- 真机接地只依赖 `vehicle_land_detected`，缺少严格备用确认；
- `test_mission` 的返航目标高度为 4 m，与目标流程的 5 m 不一致。

本设计以完整 SITL 的成功方案为默认基线，但最高目标是真机稳定完成任务。真机可基于飞行日志调整控制增益、容差、局部速度和恢复动作，不要求机械复制每一个仿真轨迹采样点。

## 2. 目标与非目标

### 2.1 目标

1. 让完整真机任务执行与 SITL 相同的任务语义：两次投放、完整侦察、返航和精准降落。
2. 保持 `test_mission` 与完整 `MissionFSM` 在运行和任务编排上彼此独立。
3. 消除真机相机内参的多来源和参数名称不一致。
4. 以少量、阶段相关的恢复机制替代固定时间后强制推进。
5. 不可恢复故障进入锁存悬停，等待遥控器接管，不由任务代码自动 RTL 或 LAND。
6. 记录计划航迹、实际轨迹、恢复事件和最终结果，使真机与 SITL 可以按任务阶段比较。
7. 保留未来重新标定相机和复测的明确方法。

### 2.2 非目标

- 不把 `test_mission` 合并成主 FSM 的 `mission_mode`。
- 不删除现有分阶段真机测试入口。
- 不以大量独立超时器追求绝对安全。
- 不覆盖 PX4 自身的电池、RC 丢失、通信和飞控 failsafe。
- 不要求真机在风和定位误差下逐点复现仿真实际轨迹。
- 不在本轮引入危险品分类或其他非当前任务功能。

## 3. 架构边界

### 3.1 两套流程独立

`test_mission` 保留自己的 ROS 节点、FSM、launch、参数和运行日志。`MissionFSM` 保留完整任务状态机。两者不互相调用状态，不共享任务进度，不通过运行模式合并。

两者只复用与具体任务无关的基础设施：

- `px4_control` 的遥测和控制接口；
- `drone_vision` 的视觉协议；
- `PathPlanner` 等无状态算法；
- 相机标定文件和 `CameraInfo`；
- 无状态的进度判断工具。

每套 FSM 分别持有进度监视器、恢复次数和等待接管状态。修改一套流程的状态顺序不会隐式改变另一套流程。

### 3.2 部署差异限制在适配层

完整 SITL 与真机继续共享 `MissionFSM`、状态实现、路径规划和任务参数。部署层只允许覆盖：

- PX4 消息版本和状态话题；
- 相机来源与标定文件；
- 舵机平台；
- Home 原点；
- 接地信号来源和仿真专用适配。

任务区域、高度、速度、yaw、容差和状态顺序不得在真机 launch 中另建一套硬编码配置。

PX4 接口以已经验证的真机部署为权威基线。源码默认保持真机 v1 `px4_msgs`，真机状态话题为 `/fmu/out/vehicle_status_v1`，真机舵机 ACK 为无版本后缀的 `/fmu/out/vehicle_command_ack`。SITL 使用隔离的 v4 overlay，并且只在 SITL 环境脚本和 launch 中显式覆盖 `/fmu/out/vehicle_status_v4`；不得为了适配 SITL 修改真机默认话题或让 v4 类型进入真机运行环境。应用层 `/drone/*` 话题在两种部署中保持一致。

## 4. 正常任务流程

### 4.1 完整任务

```text
INIT
→ 等待人工解锁
→ TAKEOFF 5 m
→ TRANSIT_TO_DROP_ZONE
→ CYLINDER_SEARCH
→ SELECT_TARGET
→ CYLINDER_APPROACH
→ DESCEND_TO_DROP
→ EXECUTE_DROP
→ ASCEND
→ 第二目标选择、精校和投放
→ TRANSIT_TO_RECON_ZONE
→ RECON_PATROL 完整弓字形扫描
→ 从最后航点立即 RETURN_TO_HOME，同时爬升至 5 m
→ Home 上方稳定
→ PRECISION_LAND
→ 接地确认、上锁、COMPLETE
```

侦察结束后不增加独立的垂直爬升状态。返航状态直接发送 Home 的 North/East 和 5 m 高度三维目标，使水平返航与爬升同时发生。

### 4.2 独立测试任务

```text
INIT
→ WAIT_ARMED
→ TAKEOFF
→ TRANSIT_FORWARD
→ DESCEND_TO_RECON
→ RECON_SWEEP
→ 从最后航点立即 RETURN，同时爬升至 5 m
→ LAND
→ COMPLETE
```

该流程保持独立，用于验证飞控、侦察路径、返航和精准降落。其正常航迹不因完整任务的投放状态修改而变化。

### 4.3 解锁前就绪门

两套真机任务在解锁前无限期等待，并周期报告缺失项。进入飞行前必须满足：

- PX4 状态和里程计持续更新；
- 电池状态有效；
- 相机协商到配置分辨率；
- 有效 `CameraInfo` 与图像尺寸一致；
- 视觉模型与首帧就绪；
- 完整任务的舵机服务和硬件状态就绪；
- PX4 preflight check 通过且操作者已用 RC 解锁。

等待人工操作不使用固定总超时。任务计时与飞行恢复逻辑从人工解锁后开始。

## 5. 相机标定单一事实来源

### 5.1 临时真机基线

在获得真实标定前，使用已经完成 `test_mission` 实飞的参数作为明确标注的临时基线：

```text
image_width: 640
image_height: 480
fx: 400.0
fy: 400.0
cx: 320.0
cy: 240.0
distortion: [0, 0, 0, 0, 0]
```

### 5.2 数据流

1. 相机节点从标准标定 YAML 加载分辨率、相机矩阵和畸变参数。
2. 相机节点发布图像及完整 `CameraInfo`。
3. 视觉管线在收到有效 `CameraInfo` 前不报告 ready。
4. 视觉管线的坐标变换、目标尺度过滤和几何计算全部使用同一份活动内参，不再读取一套初始化参数、再局部更新另一套矩阵。
5. 两套任务的图像中心来自有效 `CameraInfo`，不再由 launch 分别硬编码。
6. 图像误差控制使用归一化误差，或者从活动图像尺寸推导等效像素增益，使 1280×960 SITL 与 640×480 真机具有一致的控制含义。

标定文件路径作为真机 launch 参数保留。文档提供重新标定、替换文件、地面验证 `CameraInfo` 和回归 H 对心的方法。

## 6. 恢复与等待接管

### 6.1 基本原则

- 正常动作有持续进展时不因固定总时长中止或强制推进。
- 每个动作最多执行一次完整恢复循环。
- 恢复只重试当前动作或返回该阶段的安全检查点，不跨越任务条件。
- 恢复逻辑不得在正常路径上改变计划航迹。
- 恢复耗尽后进入 `HOLD_FOR_TAKEOVER`。

### 6.2 必要时间约束

系统只保留三类约束：

1. **数据新鲜度**：PX4 遥测、相机帧和当前阶段必需的视觉数据必须持续更新。
2. **无进展窗口**：位置、高度或视觉误差在一个观察窗口内没有达到最小改善量。
3. **命令响应**：舵机 ACK 和 ROS 服务调用必须在有限时间内完成。

无进展判断由一个无 ROS 运行依赖的进度工具计算；工具实例、窗口、改善量和恢复状态均由各 FSM 独立持有。默认只为位置航段、高度变化和视觉精校各设置一个进度监视器，不叠加全局状态超时。

### 6.3 阶段恢复规则

| 异常 | 第一次恢复 | 恢复失败 |
|---|---|---|
| PX4 状态或里程计断流 | 尽力发送零速度并等待短暂恢复 | 等待接管；由 PX4 原生通信 failsafe 处理失联 |
| 位置航点无进展 | 重发同一航点 | 等待接管 |
| 侦察航点无进展 | 重发当前航点，不跳过 | 等待接管 |
| 搜索后目标不足 | 重新执行一轮搜索路径 | 等待接管 |
| 接近阶段短暂丢失目标 | 使用目标记忆粗定位并重捕获 | 返回投放区搜索检查点 |
| 低空精校丢失或停滞 | 零水平速度、重置控制器并重捕获 | 回升至搜索高度重新搜索；再次失败后等待接管 |
| 舵机 ACK 丢失 | 重发同一个绝对 PWM 目标一次 | 等待接管，绝不推进投放位置 |
| H 暂时丢失 | 悬停、重新请求 landing 模式并重捕获 | 等待接管 |
| 任务层检测到严重低电量 | 记录并进入等待接管，不发送任务层 RTL/LAND | PX4 原生电池 failsafe 可覆盖 Offboard |
| RC 切出 Offboard 或飞行器上锁 | 视为操作者接管，停止自主输出 | 写入失败摘要，不重新进入任务 |
| 状态处理异常 | 记录 traceback | 立即等待接管 |

### 6.4 接地确认

真机以 PX4 `vehicle_land_detected.landed` 为主条件，同时启用严格备用判定。备用判定只有在已锁存视觉对心并进入垂直盲降后才有效，并要求近地高度、低水平速度、低垂直速度连续满足保持时间。默认沿用现有严格阈值：0.10 m、0.10 m/s、0.05 m/s 和 2 s；这些值作为真机待验证参数记录，不在未满足条件时强制上锁。

盲降过程只要高度仍在下降就继续。盲降停止产生高度进展时，先发送零速度；若 PX4 主信号和严格备用判定都未确认接地，则进入等待接管，不报告成功。

### 6.5 `HOLD_FOR_TAKEOVER`

两套 FSM 分别实现自己的锁存等待接管状态：

- 保存首次根因、来源状态和恢复历史；
- 持续发布零速度 Offboard 指令；
- 不自动恢复、RTL、LAND 或标记成功；
- 周期报告故障和等待接管状态；
- 检测到 RC 切出 Offboard 或飞行器上锁后，停止自主设定点输出；
- 写入失败摘要，并保留 PX4 原生 failsafe 的控制权。

等待接管期间若 PX4 因电池、RC 丢失或通信 failsafe 切换模式，任务节点立即停止与该模式竞争，不重新请求 Offboard。

## 7. 仿真基线与真机成功标准

完整 SITL 的成功结果是默认行为基线，而不是真机逐点轨迹约束。

必须保持一致的内容：

- 任务状态顺序；
- 投放目标选择和两次独立投放；
- 任务区域与路径形状；
- 侦察路径完整执行；
- 扫描后立即返航并同步爬升至 5 m；
- H 对心锁存、盲降、接地确认和上锁语义。

允许基于真机证据调整的内容：

- 控制增益；
- 到达和视觉容差；
- 局部速度；
- 数据新鲜度与进度窗口；
- 相机标定和执行器响应参数。

调整必须以真机日志为依据，并以提高完整任务成功率为判断标准。不得为了逐点复现仿真轨迹而降低真机稳定性。

## 8. 可观测性与结果记录

任务启动时记录：

- 部署类型、git 提交和 PX4 消息版本；
- 相机标定文件路径及关键内参；
- 所有计划 NED 航点、目标高度、速度和 yaw；
- 舵机绝对 PWM 序列；
- 影响恢复行为的参数。

运行时记录：

- 状态转换；
- 当前设定点与实际位姿；
- 航段进展；
- 视觉目标新鲜度和误差；
- 每次恢复的原因、动作和结果；
- 等待接管的首次根因；
- 投放、覆盖、降落和最终任务摘要。

成功摘要只在完整任务条件全部满足后写入。发送 RTL、LAND、进入等待接管或操作者接管均不能记录为自主任务成功。

## 9. 验证策略

### 9.1 自动测试

- 相机标定只有一个活动来源，`CameraInfo` 与图像尺寸一致；
- 视觉几何和尺度过滤使用同一份活动内参；
- 两套 FSM 的状态和运行数据彼此独立；
- 两套返航目标均为 Home 上方 5 m，且没有独立先爬升状态；
- 超时不能强制推进、跳过必需航点或报告成功；
- 每个恢复动作只发生一次，恢复耗尽进入等待接管；
- 舵机重试保持相同绝对 PWM；
- 接地备用判定未满足全部条件时不能上锁；
- 当前删除文档导致的测试契约失败被修复，测试不再依赖不存在的文件。

### 9.2 SITL 回归

1. 运行全部相关单元和契约测试。
2. 运行完整 SITL，验证两次投放、完整侦察、同步爬升返航、H 对心、盲降和成功摘要。
3. 注入短暂视觉丢失、航点停滞和 ACK 延迟，验证单次恢复后继续任务。
4. 注入持续故障，验证进入等待接管且不自动 RTL/LAND。

### 9.3 真机分阶段验收

1. 相机单独检查，记录临时标定并验证图像、`CameraInfo` 和中心点。
2. 无桨验证 DDS、完整启动就绪门和两次舵机绝对位置。
3. 复飞独立 `test_mission`，确认从最后侦察航点直接返航并同步爬升至 5 m。
4. 完整系统地面启动但不解锁，验证无限等待和缺失项诊断。
5. 逐步验证投放搜索、单次投放、两次投放。
6. 最终执行完整真机任务，以任务成功率和阶段日志评估是否需要真机参数调整。

## 10. 完成标准

代码层完成标准：

- 本设计中的运行边界、恢复规则、相机单一来源和日志要求均有自动测试；
- 相关测试、构建和完整 SITL 回归通过；
- 操作文档包含标定替换、地面检查、分阶段实飞和等待接管说明。

最终真机完成标准：

- 两次目标投放成功；
- 侦察路径完整执行；
- 从最后侦察航点直接返航并在途中爬升至 5 m；
- Home 上方完成 H 视觉对心、盲降、接地确认和上锁；
- 正常路径未触发恢复；若出现可恢复异常，恢复后仍完成任务；
- 任务摘要真实反映成功或失败，不以降级动作掩盖未完成条件。
