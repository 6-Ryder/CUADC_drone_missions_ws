# 任意场地方位任务设计

**状态：** 已确认，待书面复核

**日期：** 2026-08-12

**范围：** 主任务与快速策略两套完整流程的场地几何、飞机航向、视觉坐标、覆盖监控和 SITL 场地

## 1. 目标

让当前以正北为前方的两套完整任务策略都能够沿任意场地方位运行。例如，
`layout_heading_deg=50.0` 表示整套任务场地的前方相对 NED 正北顺时针
旋转 50°。除绝对方位外，任务区域尺寸、相对距离、状态顺序、投放策略、
侦察路径、返航、精准降落和飞行速度均保持当前行为。

两套必须覆盖的完整流程是：

- **主任务策略：** `sitl.launch.py` / `real_flight.launch.py`，加载
  `mission_params.yaml` / `mission_params_real.yaml`；
- **快速策略：** `quick_sitl.launch.py` / `quick_flight.launch.py`，加载
  `mission_params_quick_sim.yaml` / `mission_params_quick.yaml`。

两套策略共享同一 MissionFSM、坐标变换和飞行控制链，只通过现有参数选择
投放、视觉和降落行为。本设计不得复制一套“快速方向逻辑”或让快速策略绕过
公共 `LayoutFrame`。独立的 `simple_mission` 不属于这两套完整流程。

本次改造以当前快速策略为权威行为基线。共享环节出现参数、状态语义或实现
路径歧义时，先保证快速策略现有流程除绝对方位外完全不变，再让主任务接入
同一公共能力。不得为了迁就主任务分支而改变快速策略已经采用的投放方式、
`marker_only`视觉模式、连续投放伺服、简化降落、速度或状态完成条件。主任务
自身特有的精准降落等行为仍保留，但不作为本次方向改造的定义来源。

“快速策略为准”不表示可以破坏主任务。主任务当前的投放、侦察、返航、精准
降落、恢复和完成条件必须通过0°不回归测试；快速策略当前的对应流程也必须
通过0°不回归测试。方向参数化只允许改变绝对水平坐标和目标yaw，不允许借机
统一、替换或重写两套策略原本不同的任务行为。

飞机、任务轨迹、视觉覆盖网格和 SITL 场地使用同一个方位值。飞机从
Offboard 起飞开始即以该方位为目标 yaw，在爬升的同时转向，不增加独立的
对准状态或等待时间。任务完成效率至关重要；50°任务不应因航向参数化增加
额外等待或无意义的条带转向。验证以快速策略为首要端到端基线，主任务随后
执行完整回归。

PX4 的标准 NED 世界坐标保持不变。本设计是在 NED 上建立场地局部坐标系，
不是重置 EKF yaw、重定义 GPS 北向或把飞机上电时的随机机头方向当作世界
坐标零度。

## 2. 已确认的设计决策

| 项目 | 决策 |
|---|---|
| 场地方位来源 | 启动前显式配置的绝对 NED 方位 |
| 参数 | `layout_heading_deg`，度，0=正北，顺时针为正 |
| 默认值 | `0.0`；本次首个非零示例为 `50.0` |
| 生效时间 | 单次任务启动时确定，飞行中不可修改 |
| 场地范围 | 起降区、H、起飞线、投放区、侦察区、目标和边界整体旋转 |
| 飞机 yaw | 全任务保持 `layout_heading_deg`，不跟随航迹方向 |
| 起飞 | 原解锁、Offboard、高度和稳定判定不变；爬升与转向并行 |
| yaw 放行门槛 | 无；未完全转到目标 yaw 也可进入下一状态并继续收敛 |
| 旧参数 | 删除 `flight_axis`、`drop_distance`、`recon_distance`，不保留兼容层 |
| 旧 yaw 模式 | 删除 `follow_path`/`yaw_mode` 设计，不提供第二种策略 |
| 视觉姿态缺失 | 可保留像素检测，但不得生成或记忆世界坐标目标 |
| SITL 初始姿态 | Gazebo ENU yaw 随场地施加 `-heading` 旋转，以保持与北向基线相同的初始相对姿态 |
| 策略覆盖 | 主任务和快速策略均必须完整支持，不允许只修改其中一套 launch/配置 |
| 权威行为基线 | 当前快速策略；出现歧义时不得用主任务行为覆盖快速策略 |
| 实施与验证优先级 | 先完成快速策略方向闭环和效率验收，再接入并回归主任务 |
| 不回归边界 | 快速策略、主任务及默认0°北向行为均不得被破坏 |

## 3. 坐标模型

### 3.1 场地局部坐标

以 Home 的 NED 水平位置为原点定义右手局部平面：

- `forward`（或数学符号 `u`）：场地前方，方位为 `layout_heading_deg`；
- `right`（或数学符号 `v`）：面对场地前方时的右侧，方位为
  `layout_heading_deg + 90°`；
- 高度继续使用现有 NED down/World up 约定，不参与水平旋转。

令 `h = radians(layout_heading_deg)`，局部坐标到 NED 的变换为：

```text
north = forward * cos(h) - right * sin(h)
east  = forward * sin(h) + right * cos(h)
```

NED 到局部坐标的逆变换为：

```text
forward = north * cos(h) + east * sin(h)
right   = -north * sin(h) + east * cos(h)
```

所有角度输入只要是有限数值就合法。入口将其归一化到 `[0°, 360°)`；传给
PX4 的 yaw 再归一化到其要求的 `[-π, π]` 等价范围。因此 410°等价50°，
-10°等价350°。

### 3.2 单一变换模块

在 `drone_utils` 中建立唯一的 `LayoutFrame`，负责：

- 角度验证和归一化；
- `local_to_ned(forward, right)`；
- `ned_to_local(north, east)`；
- Home 相对 NED 与现有 World 坐标之间的组合转换；
- 点是否位于局部旋转矩形内的精确判定；
- 局部区域中心和角点计算。

任务状态、路径规划、视觉覆盖和场地工具不得各自复制旋转公式。模块不保存
飞行状态，也不读取 ROS 参数；调用方在启动时构造后只读使用。

### 3.3 区域参数迁移

区域继续保存当前数值，但名称和语义改为场地局部坐标：

```yaml
area1_forward_min: 30.0
area1_forward_max: 35.0
area1_right_min: -4.0
area1_right_max: 4.0

area2_forward_min: 55.0
area2_forward_max: 60.0
area2_right_min: -4.0
area2_right_max: 4.0

sweep_margin_forward: 1.0
sweep_margin_right: 0.5
```

投放区和侦察区转场中心分别从区域边界计算，仍为局部
`(32.5, 0.0)` 和 `(57.5, 0.0)`。删除重复的 `drop_distance` 和
`recon_distance`，防止中心距离与区域边界产生两套真值。

删除 `area*_north_*`、`area*_east_*`、`sweep_margin_north/east` 和
`flight_axis`。所有配置、launch、测试和文档一次性迁移，不通过旧参数推断
新值。

## 4. 参数所有权与数据流

`layout_heading_deg` 是每次启动的唯一场地方位值，默认0°，不可在飞行中动态
更新。主任务和快速策略的仿真/真机四个 launch 均声明同名参数并传入同一
公共实现；相应四个参数配置同步完成旧字段迁移。

```text
SITL 启动入口 --layout-heading-deg
        ├── 运行时 SDF 生成器
        ├── PX4_GZ_MODEL_POSE 初始 yaw
        └── ROS 2 launch 参数
              ├── MissionFSM / FlightController
              └── VisionPipeline / CoverageMonitor
```

快速SITL先建立并验证上述完整数据流，主任务SITL复用同一实现。最终
`start_quick_simulation.sh` 和 `start_full_simulation.sh` 都必须支持同一方向
参数，任何一个仍加载固定北向场地都不算完成。真机没有 SDF 分支，同一
launch 参数传给任务和视觉。Python 参数声明可提供0°缺省值，但 YAML 和节点
不得再定义互相覆盖的第二个运行时方向来源。

启动日志必须记录：原始输入角度、归一化角度、Home、投放区中心、侦察区
中心和所使用的运行时 SDF。非法或非有限角度必须在 Arm 之前使启动失败，
而不是只记录警告后继续。

## 5. 飞行控制设计

### 5.1 任务级默认 yaw

`FlightController` 保存一次只读的任务 yaw。设置后，下列位置和速度接口默认
使用它，不再默认0°：

- `takeoff()`；
- `loiter()`；
- `goto_ned()` / `goto_world()`；
- `set_velocity_ned()` / `set_velocity_body()`；
- `stop_velocity()` 和接管等待悬停。

这是一条控制层不变量，不依赖每个任务状态重复传入 yaw。完整
`MissionFSM` 不提供按状态覆盖任务 yaw 的路径。

### 5.2 起飞与效率

现有 TAKEOFF 的 RC 解锁、仿真自动解锁、Offboard 预流、模式确认、目标高度、
高度容差、稳定计数、无进展重试和接管行为原样保留。

Offboard 位置预流和随后的起飞位置指令携带任务 yaw。PX4 进入 Offboard 后，
飞机并行执行垂直爬升和偏航转向。达到现有起飞完成条件后立即进入
`TRANSIT_TO_DROP_ZONE`；不新增 `ALIGN_LAYOUT_HEADING`，不检查 yaw 容差，
也不设置 yaw 对准超时。若进入中转时仍有偏航误差，PX4 在飞行中继续收敛。

### 5.3 位置和速度模式连续性

当前位置模式向 PX4 发布绝对 yaw，而速度模式发布 `yaw=NaN`。实现必须改为：

- 桥接层持续保存最近的任务绝对 yaw；
- 速度 `TrajectorySetpoint` 的 `yaw` 继续发布该绝对值；
- 速度和位置 `TrajectorySetpoint` 的 `yawspeed` 显式设为NaN，避免与绝对
  yaw 形成第二个偏航目标；
- 本任务不使用 yaw-rate 改变机头方向；
- 从位置切换到视觉速度、停止速度或接管悬停时不清空 yaw 目标；
- 回到位置模式时仍使用同一个目标。

不新增 ROS 消息，也不把 `Twist.angular.z` 从 yaw-rate 偷换成绝对 yaw。现有
位置指令已在任何速度阶段之前建立任务 yaw，桥接层保持它即可。契约测试必须
锁定此顺序和行为。

`set_velocity_body()` 继续使用实时测得的实际 yaw 将机体系 forward/right
速度旋转到 NED；不能用目标 yaw 代替实际 yaw。这样飞机在转向过程中，图像
控制指令仍对应当前机体方向。

### 5.4 各状态的航向语义

TAKEOFF、区域中转、圆筒搜索、圆筒接近、投放下降、投放后上升、侦察覆盖、
返航、主任务精准降落、快速策略简化降落和 `HOLD_FOR_TAKEOVER` 均使用任务
yaw。快速策略的 `quick_drop_mode`、`marker_only`、连续投放伺服和 simple
landing 只改变既有任务行为，不改变场地方位的来源或控制契约。

侦察弓字路径只旋转位置，不随往返条带产生0/π或±π/2的机头转向。该策略
保持下视相机相对场地的固定姿态，并消除无功能价值的180°旋转时间。

## 6. 路径与区域安全

路径规划器在 `forward/right` 局部区域内执行当前弓字形算法，包括当前
条带间距、速度、往返顺序和高度。`sweep_margin_forward/right` 只做语义重命名；
当前规划器虽保存该配置却未把它用于条带端点，本次不得顺带启用，以保证0°
输出逐项不变。生成完成后，每个水平航点通过
`LayoutFrame.local_to_ned()` 转换。0°时输出必须与当前北向任务逐项一致。

投放区和侦察区中心、圆筒搜索横穿端点、覆盖航点及返航前的任务点均采用
同一变换。Home 是旋转原点，因此返航目标位置不随 heading 改变。

世界坐标目标的投放区安全判定必须执行：

```text
World XY -> Home 相对 NED -> 场地局部 forward/right -> 局部矩形判定
```

margin 在局部四条边上按现有数值扩展或收缩。禁止使用旋转矩形的 World
轴对齐外接框，否则斜向场地会接受实际位于投放区外的目标。

## 7. 视觉与覆盖契约

### 7.1 世界坐标投影

主视觉投影继续使用飞机完整6DoF位姿和相机外参。该计算天然支持非零yaw，
不增加以任务 heading 代替实际姿态的补偿。

删除任务目标路径中“机头朝北”的简化世界坐标回退。视觉节点记录最近一次
有效姿态时间；姿态未收到、四元数无效或消息年龄超过
`vision_pose_max_age_s=0.5` 时：

- 可发布目标像素中心、边界框和置信度；
- 世界坐标字段标记为不可用；
- 不把该检测加入圆筒或标志物世界坐标记忆；
- 任务不得据此发送世界位置航点。

像素闭环只在其所属状态已有合法目标锁定并满足现有安全条件时继续运行；本
设计不放宽投放或降落的置信度、稳定帧和释放条件。

### 7.2 消息坐标语义

`CylinderDetection.center_x/center_y` 当前注释为 NED、实际发布为 World，任务
还会猜测两种解释。新契约改为显式 `world_x/world_y`，并要求
`CylinderArray.header.frame_id="world"`。圆筒和蓝色投放标志使用相同语义。

任务层删除 World/NED 猜测与兼容转换。`CylinderDetection` 新增
`bool world_position_valid`；有效时 `world_x/world_y` 是World坐标，无效时该
布尔值为false且两个浮点字段写入NaN。无有效世界坐标的检测不能伪装成
`(0, 0)`，消费者必须先检查有效位，不得恢复双重坐标解释。

危险品分类不在当前完整任务路径中，本设计不扩展其业务逻辑；若其消息被
本次字段迁移影响，只同步坐标命名和注释，不增加分类功能。

### 7.3 覆盖监控

覆盖网格直接建立在侦察区局部 `coverage_zone_forward_min/max` 和
`coverage_zone_right_min/max` 范围。每次更新先将飞机World位置转换到局部
坐标，再使用现有高度、FOV和网格分辨率标记覆盖。

覆盖计算不使用旋转区域的 World AABB。对于同一条局部航迹，0°和50°必须
得到相同网格尺寸、相同被覆盖单元序列和相同最终覆盖率（允许浮点容差）。

## 8. SITL 场地

`field/drone_field.sdf` 保持0°北向的规范模板。启动时生成临时运行时SDF，
以 Home `(world_x=4, world_y=10)` 为中心旋转所有任务资产：

- 场地底板和边界；
- 准备区、起降区、投放区、间隔区和侦察区；
- 起降圆、H和起飞线；
- 投放/侦察圆筒、有效区圆盘和危险品标志板；
- 场地角标和任务区域角标。

这里必须显式处理 NED/ENU 的正方向差异。`layout_heading_deg` 在 NED 中从北
顺时针为正，而 Gazebo World yaw 在 ENU 中逆时针为正。令规范资产相对Home
的World偏移为 `(dx, dy)`，则运行时World变换是：

```text
world_x' = home_x + dx*cos(h) + dy*sin(h)
world_y' = home_y - dx*sin(h) + dy*cos(h)
world_yaw' = world_yaw - h
```

因此规范场地正北方向上的点在 `h=50°` 时应移动到东北象限，而不是西北象限。
SDF和 `PX4_GZ_MODEL_POSE` 使用的是Gazebo ENU yaw，不能直接填入PX4的正向
`h`。

无限地面、物理、重力、磁场、天空、太阳和GUI观察相机属于环境，不参与
任务场地旋转。

随机场地生成必须先在规范局部区域中采样，再旋转到World。现有生成器中
投放/侦察区把World X/Y与North/East混用的问题必须先修正。固定随机种子时，
0°和50°生成物逆旋转回局部坐标后必须完全一致。

SITL飞机仍生成在Home；其原始Gazebo yaw在0°保持当前基线值，在任意heading
下与场地一起减去 `h`。这使场地、H、相机和机头的初始相对关系与0°基线
相同。PX4收到的任务绝对yaw仍是正向的 `h`，若换算后的初始PX4 yaw与目标
有偏差，飞控按既定策略在起飞过程中修正。

规范SDF不得被运行时生成覆盖。启动脚本使用临时输出，并把同一个heading
传给SDF生成、PX4模型姿态和ROS launch。

## 9. 错误处理

- heading 非有限：Arm前失败；
- heading 超出一圈：归一化，不视为错误；
- 飞行中尝试修改heading：拒绝，当前任务继续使用启动值；
- 视觉姿态无效或过期：丢弃世界坐标，不猜测北向；
- 目标落在旋转投放区外：丢弃并记录局部坐标诊断；
- 实际yaw暂未达到目标：继续任务并持续发送目标，不触发新状态或超时；
- 原有PX4模式丢失、无进展、视觉丢失和人工接管策略保持不变。

SITL通过单一启动值避免场地与任务heading不一致。真机无法从代码自动验证
实体场地方位，启动日志必须醒目打印heading，由操作者确认飞机和场地摆放。

## 10. 验证与效率验收

### 10.1 纯函数和几何

- 多个正、负和大于360°角度的归一化；
- 局部/NED正反变换互逆；
- 0°、50°、90°、180°和临界角；
- 区域中心由边界唯一导出；
- 旋转矩形内外点与margin；
- 0°航点逐项等于当前北向基线；
- 任意heading的航点逆旋转后等于0°局部航点；
- 旋转前后路径总长度相等。

### 10.2 控制契约

- Offboard预流和起飞目标携带任务yaw；
- 起飞高度与稳定判定未改变；
- TAKEOFF直接进入中转，无航向等待状态；
- 位置模式、速度模式、停止速度和接管悬停均发布任务yaw；
- 位置/速度往返切换不丢yaw；
- body速度使用实际yaw转换；
- 侦察全部航点保持同一yaw，不产生条带反向转头。

### 10.3 视觉、覆盖和场地

- 50°实际四元数投影得到正确World目标；
- 无姿态、无效姿态和超过0.5秒的姿态不生成World目标；
- 消息只存在一种World坐标解释；
- 0°和50°覆盖网格逆变换后等价；
- 运行时SDF中每个任务资产的位置和yaw均为绕Home的正确旋转；
- 环境资产保持不变；
- SITL模型与场地施加相同的Gazebo `-heading` yaw增量，0°原始姿态不变；
- 随机场地固定种子旋转不变量成立。

### 10.4 快速策略核心端到端效率

使用相同代码、参数、固定随机场地种子和仿真环境，分别运行0°与50°完整
快速SITL任务。两者都必须完成快速策略既有投放、侦察、返航和简化降落成功
条件。任意方向功能的首个端到端调试、性能比较和通过判定均以快速策略为
核心，不等待主任务先完成验证。

快速策略的0°回归是行为兼容的权威比较对象。状态序列、快速投放控制、
`marker_only`检测、简化降落及其完成条件不得因公共方向抽象而向主任务行为
靠拢。

效率以各方向至少3次成功运行的任务完成时间中位数比较：

```text
median(time_50deg) <= 1.05 * median(time_0deg)
```

日志还必须证明50°路径没有新增等待状态，侦察条带没有yaw往返旋转，局部
路径长度与0°一致。若超出5%，先区分普通仿真波动、PX4转向动态和新增代码
等待；不得通过放宽投放、覆盖或降落成功条件来满足时间指标。

### 10.5 主任务完整回归

快速策略通过后，主任务SITL必须分别完成至少一次0°和50°全流程，验证主任务
投放、侦察、返航和精准降落没有被快速策略专用分支掩盖。主任务不承担本次
首要5%性能门槛，但不得出现新增航向等待状态，逆旋转后的局部路径仍须与0°
一致。

部署契约测试必须覆盖主任务/快速策略 × SITL/真机四个 launch 和四套参数，
证明 `layout_heading_deg` 均能到达任务与视觉节点，旧方向参数均已删除。只在
快速SITL成功而主任务launch仍固定北向，不算实现完成。

## 11. 实施范围与非目标

预计涉及：`drone_utils`坐标工具、`drone_mission`四套配置/FSM/路径与区域状态、
`px4_control`位置和速度yaw契约、`drone_vision`投影消息与覆盖、四套完整任务
launch、主任务与快速策略SITL启动脚本、场地生成器、接口消息、测试及相关
文档。

以下不属于本设计：

- 重置PX4 EKF yaw或改变NED定义；
- 用飞机初始yaw自动决定场地方位；
- 飞行中动态旋转任务；
- 为投放区和侦察区设置不同heading；
- 跟随航迹方向转头；
- 改变任务速度、区域尺寸、相对距离、投放/降落阈值或任务顺序；
- 新增航向等待、航向超时或航向失败接管策略；
- 扩展危险品识别任务。

独立的 `simple_mission` 和历史测试工具不作为完整任务入口；快速策略是
MissionFSM 的完整快速流程，不等同于 `simple_mission`。历史工具若因共享接口
变化而需要迁移，只做编译/运行兼容，不为它们新增任意方向任务能力。

## 12. 取代的旧方案

本规格取代 `docs/Tactics/PLAN_recon_yaw_heading_param.md`。旧文档中局部坐标
旋转、局部覆盖网格和精确旋转矩形判定继续有效；以下设计不再采用：

- `flight_heading_deg` 命名；
- `flight_axis` 兼容映射；
- `yaw_mode="hold"` 时保持绝对0°；
- 可选 `follow_path`；
- 只旋转任务坐标而不旋转完整SITL场地；
- 不处理起飞、速度模式和视觉姿态有效性的有限改动范围。
