# 视觉误检根因分析 & 综合优化方案

> 2026-07-16 | 全类别视觉误检（非目标物体被识别和定位）系统性分析

---

## 一、问题概述

视觉管线在所有检测类别（圆筒、投放区蓝色标识、降落 H 标识）上，在 SITL 与真机两种环境下，均存在将非目标背景/杂物识别为目标的问题。画面中被识别和定位的往往不止目标物体，很多杂物和背景也被识别到。

---

## 二、当前架构回顾

```
Camera(1280×960) → YOLO(640×640) → OpenCV 后处理 → 输出
                      ↑                  ↑
                 单类模型            无形状/时序约束
```

两个独立单类 YOLO 模型：
- `cylinder_yolo.pt` (YOLOv8n): 白色圆筒检测
- `drop_marker_yolo.pt` (YOLO11n): 蓝色投放区标识检测
- H 降落标识: 无专用模型, 依赖 `LandingPadRefiner` OpenCV 后处理

---

## 三、根因分析

### 3.1 OpenCV 管线架构缺陷：精修而非验证

OpenCV 在当前管线中的角色是"精修器"而非"验证器"——精修失败不拒绝检测，只回退到 YOLO 原始结果：

**圆筒** (`vision_pipeline.py:571-578`)：
```python
if result:
    refined.append((*result, bbox_px))
elif d.confidence > 0.7:   # 精修失败但置信度高 → 仍然保留！
    refined.append((...))
```

**投放区标识** (`vision_pipeline.py:456-464`)：
```python
refined_cx, refined_cy, refined_ok = self._refine_marker_center(...)
use_cx = refined_cx if refined_ok else md.cx    # 精修失败 → 直接回退 YOLO！
use_cy = refined_cy if refined_ok else md.cy
```
**完全不拒绝**。无论 OpenCV 能不能找到蓝色圆圈，YOLO 的 bbox 中心一定被输出。

**降落 H 标识** (`vision_pipeline.py:671-684`)：
```python
target.center_u = best.cx     # 精修失败 → 回退 YOLO
target.center_v = best.cy
```
同样**不拒绝**。

### 3.2 各检测器 OpenCV 算法问题

#### 3.2.1 CylinderRefiner — Canny + fitEllipse 太通用

| 问题 | 后果 |
|------|------|
| Canny 边缘对纹理区域敏感（草地、沙地、杂物表面） | 任何有纹理的背景都会产生大量边缘 |
| `fitEllipse()` 只要有 5 个点就能拟合 | 非圆形的随机边缘点也能"拟合成功" |
| 中心白度只采样 **1 个像素** | 一个白色噪点就能通过 |
| 没有**边缘梯度方向一致性**检查 | 圆筒开口边缘的梯度应指向圆心；随机纹理的梯度指向各方向 |
| 评分函数 `area × circularity` 忽略几何约束 | 面积大但不圆的不规则轮廓也能拿高分 |
| 没有空心结构验证 | 白色实心物体（石头、纸片）也能通过 |

#### 3.2.2 _refine_marker_center — 本质是蓝色色块检测器

| 问题 | 具体数值 | 后果 |
|------|---------|------|
| H 范围过宽 | [95, 135] 跨度 40° | 天空蓝(~100)到深蓝紫(~135)全被纳入 |
| **S 下限太低** | 60 | 灰蓝色（接近灰色）也能通过；真实蓝色标识 S > 120 |
| **V 下限太低** | 60 | 阴影中的暗蓝色通过 |
| **面积阈值太低** | 80 px²（约 9×9 像素） | 任何蓝色小碎屑都能通过 |
| **没有圆形度检查** | 未计算 | 长条形蓝色胶带、矩形标记都能通过 |
| **没有预期半径检查** | 已知标识 Ø1m，未利用 | 高度 3m 时预期 ~130px 半径，但 20px 也能过 |
| 形态学 kernel (5,5) | 可合并噪声成"大轮廓" | 多个小噪声被合成一个假目标 |

#### 3.2.3 LandingPadRefiner — 不验证 H 字形

| 问题 | 后果 |
|------|------|
| 自适应阈值 `block=11, C=2` | 对局部纹理极度敏感；草地纹理被增强成"轮廓" |
| `minEnclosingCircle()` 总是能套外接圆 | 正方形、长条形的外接圆也能通过 circularity > 0.6 |
| circularity > 0.6 太宽松 | 正六边形 circularity ≈ 0.83 |
| **没有 H 字形验证** | 圆形底板里有 H 字母！当前完全不验证 H 的存在 |
| `_estimate_h_orientation()` 只用于输出 yaw | 方向估计结果没有被用来**拒绝非 H 目标** |
| ROI margin=10 太大 | 高空时 bbox 紧，扩展 10px 包含大量无关背景 |

### 3.3 时序与冗余层面

| 层 | 问题 | 为什么导致误检 |
|----|------|---------------|
| **模型层** | 单类模型 (1 class) 无负样本意识 | 只知道"这是什么"，不知道"这不是什么"。任何相似纹理/形状的背景都被归类为正类 |
| **训练层** | 仿真数据背景干净，缺真实场景 clutter | 训练时全是目标+干净背景，推理时遇到草地、阴影、杂物 → 模型没见过抑制信号 |
| **推理层** | conf_threshold=0.5，高空自适应降到 ~0.2 | 大量低置信度假阳性直接通过。640×640 下远处目标仅几十像素 |
| **时序层** | 仅圆筒有 tracker (min_hits=3)；投放标识和 H 标识无追踪 | 单帧闪烁误检直接输出到伺服/PID |
| **冗余层** | YOLO 和 OpenCV 是"串行接力"不是"并行交叉验证" | 精修失败回退 YOLO bbox 中心，没有"双方必须同时确认"的硬约束 |

### 3.4 责任比重

| 环节 | 贡献误检占比 | 关键问题 |
|------|:---:|------|
| **OpenCV 算法能力弱** | ~45% | 精修失败不拒绝、HSV 范围太宽、圆形度不检查、缺 H 形验证 |
| **YOLO 模型训练不足** | ~35% | 单类模型无负样本意识、仿真数据缺 clutter |
| **缺失时序/冗余滤波** | ~20% | 无追踪(除圆筒)、单帧误检直接输出、YOLO/OpenCV 串行不交叉验证 |

## 四、综合优化方案

### 设计原则

1. **OpenCV 从"精修器"升级为"验证器"** — 精修失败不是回退 YOLO，而是拒绝检测
2. **高度自适应** — 高空依赖 YOLO（CV 做不到），低空强制交叉验证（CV 做得最好）
3. **不增延迟、不掉帧** — 所有新增计算量控制在每帧 3ms 以内

---

### 第 1 层：管线逻辑修正（最优先，改动最小，效果最大）

#### 核心改动：OpenCV 验证失败 → 拒绝，不回退

```
当前逻辑：
  YOLO bbox → OpenCV 精修 → 成功 → 使用精修结果
                           → 失败 → 使用 YOLO 原始结果  ← 这个分支制造了大部分误检

修正后：
  YOLO bbox → OpenCV 验证 → 成功 → 输出
                           → 失败 → 拒绝（不输出）
```

#### 高度分层策略（保护高空目标召回率）

| 高度范围 | YOLO conf 要求 | OpenCV 验证 | 理由 |
|----------|:---:|------|------|
| > 8m（高空搜索） | ≥ 0.7 | **跳过** | 目标像素太少，CV 不可靠 |
| 3m–8m（中空过渡） | ≥ 0.5 | **必须通过** | 目标已够大，CV 可有效工作 |
| < 3m（低空精校/降落） | ≥ 0.4 | **必须通过 + 严格约束** | 低空 CV 精度最高，收紧参数 |

```
场景示例:
高度 8m：YOLO 检出，conf=0.75 → 直接输出 ✓ (CV 可能找不到，不强制)
高度 5m：YOLO 检出，conf=0.55 → OpenCV 验证 → 找到白色椭圆 → 输出 ✓
                                           → 找不到 → 拒绝 ✗
高度 2m：YOLO 检出，conf=0.42 → OpenCV 验证 → 合格 → 输出 ✓
                                            → 不合格 → 拒绝 ✗
```

**对精度的影响**: 高空不验证 → 召回率不受损。低空强制验证 → 精确率大幅提升。

**对延迟的影响**: 仅增加 `if altitude > 8.0` 分支判断，零额外延迟。

---

### 第 2 层：OpenCV 算法能力增强（每帧增加 ~2ms）

#### 2a. CylinderRefiner 升级

三层验证替代当前的单点白度：

**① 椭圆拟合质量检查（已有，收紧参数）**
- 偏心率: `r_min/r_max > 0.7`（当前 0.5）
- 椭圆上采样 8 个点，检查梯度方向是否指向圆心
- 偏离 > 30° 的点超过 2 个 → 拒绝
- 计算量: 8 次 atan2, < 0.2ms

**② 白度区域统计（替代单点采样）**
- 在拟合椭圆内圈（0.3r ~ 0.8r 环形区域）统计 V>120 的像素占比
- 白色占比 < 50% → 拒绝
- 计算量: 环形 mask + 像素统计, < 0.5ms

**③ 空心结构验证（新增，核心区分能力）**
- 圆筒开口特征: 白色边缘环 + 内部暗色空洞
- 椭圆中心 0.3r 半径圆内 V 均值 vs 环形白色区域 V 均值
- 差值 < 40 → 可能是实心白色物体（石头、纸片），拒绝
- 计算量: 双区域 mask 统计, < 0.5ms

#### 2b. 投放区标识 _refine_marker_center 升级

五层过滤替代当前的"面积 > 80"：

| 验证步骤 | 当前 | 改为 | 计算量 |
|----------|------|------|:---:|
| HSV H 范围 | [95, 135] | [100, 125] | 零 |
| HSV S 下限 | 60 | 100 | 零 |
| HSV V 下限 | 60 | 80 | 零 |
| 面积阈值 | 固定 80 px² | 自适应: `max(π×(0.5×f/h)² × 0.3, 200)` | < 0.01ms |
| 圆形度 | 无 | `4π×area/perimeter² > 0.75` | < 0.1ms |
| 凸性 | 无 | `area/convexHull面积 > 0.85` | < 0.3ms |

精修失败 → 拒绝（不 fallback 到 YOLO 中心）。

#### 2c. LandingPadRefiner 升级

**① 圆形检测保持**，circularity: 0.6 → 0.75

**② 新增 H 字形验证（最关键）**
- 在检测到的圆内做 OTSU 二值化
- 统计竖方向 (y 轴) 像素投影直方图: 应呈现"双峰"特征（H 两条竖线）
- 统计横方向 (x 轴) 像素投影直方图: 应呈现"单峰"特征（H 横条）
- 没有 H 特征 → 拒绝
- 计算量: 投影直方图（两次 np.sum），< 0.5ms

**③ block 大小自适应**: `block = max(11, bbox_min_dim / 4)`

**④ 精修失败 → 拒绝**

---

### 第 3 层：时序一致性（不增延迟，增启动确认帧数）

#### 3a. 所有检测类型统一加追踪

当前仅圆筒有 `CylinderTracker`（min_hits=3）。改为三种检测各独立 tracker。

#### 3b. 双通道输出：confirmed / unconfirmed

```
Tracker 状态:
  hits=0 (新出现)   → "unconfirmed"
  hits=1-2 (累积中) → "unconfirmed"  
  hits≥3 (确认)     → "confirmed"
```

- **不掉帧**: 每帧都有输出
- **不影响响应速度**: mission 层可根据当前阶段决定是否使用未确认检测
- **不影响精度**: 确认目标经过 3 帧验证，位置通过 tracker 做亚帧平滑

| 检测类型 | min_hits | max_age | 说明 |
|----------|:---:|:---:|------|
| 圆筒 | 3（保持） | 10 | 搜索阶段可能有多个圆筒进出视野 |
| 投放区标识 | 2 | 15 | 低空精校阶段几乎一直在视野 |
| 降落 H | 2 | 15 | 降落需要快速响应 |

**延迟影响**: tracker.update() 是纯数值计算，新增两个 tracker < 0.5ms。

### 第 4 层：场景几何先验（零延迟）

利用场地布局和 `/drone/pose` 做硬过滤（在姿态补偿坐标变换后执行）：

| 规则 | 预期效果 |
|------|---------|
| world_xy 距离投放区中心 > 8m → 不可能是圆筒或标识 → 拒绝 | 过滤侦察区误检 |
| world_xy 距离 H 点 > 5m → 不可能是降落标识 → 拒绝 | 过滤投放区出现的"假 H" |
| world_xy Z > 1m → 不可能是地面目标 → 拒绝 | 过滤空中悬浮物误检 |

### 第 5 层：模型重训（并行准备，1-3 天）

#### 5a. 合并为单模型多类

```
当前: cylinder_yolo.pt (1类) + drop_marker_yolo.pt (1类) → 分开推理
改进: drone_yolo.pt (6类 + 1 背景类) → 单次推理

类别: cylinder, flammable, health_hazard, danger, landing_H, empty_cylinder, background
```

好处:
- 推理从两次变成一次 → **减少延迟**
- 多类互斥信号帮助抑制误检
- 单模型权重共享 → backbone 特征更丰富

#### 5b. 负样本（background 类）采集策略

| 来源 | 采集方式 | 预期数量 |
|------|---------|:---:|
| 仿真全图随机 crop | 不含任何目标的区域，512×512 随机 crop | 2000+ |
| 仿真中 YOLO FP | 当前模型推理，收集 conf>0.3 但不在 GT 中的 bbox | 500+ |
| 实飞录像 | 收集 FP | 300+ |
| 公开航拍数据集 | VisDrone/UAVDT 中不相关场景 crop | 1000+ |

#### 5c. 训练增强升级

| 增强参数 | 当前值 | 改为 | 理由 |
|----------|:---:|:---:|------|
| copy_paste | 无 | 0.3 | 目标随机贴入不同背景 |
| blur | 无 | 0.1 | 运动模糊（模拟飞行振动）|
| noise | 无 | 0.05 | 高斯噪声（模拟低光）|
| mosaic | 0.5 | 0.3 | 适度降低 |
| mixup | 0.1 | 0.05 | 降低（混合可能模糊目标边界）|
| scale | 0.3 | 0.5 | 加大缩放范围（模拟更极端高度）|
| degrees | 5 | 10 | 放宽旋转角度 |

#### 5d. 模型选择

| 参数 | 当前 | 建议 | 理由 |
|------|------|------|------|
| 架构 | YOLOv8n (3.2M) | YOLOv8s (11.2M) 或 YOLOv8m (25.9M) | 更大 backbone 更强的特征区分能力 |
| 输入尺寸 | 640×640 | 保持 | Jetson 实时约束 |

## 六、实施顺序与依赖

```
第 1 层 ─── 管线逻辑修正 ─── 依赖：无 ─── 耗时：2h ─── 消除 ~50% 误检
    │
    ├─ 第 2 层 ─── OpenCV 算法增强 ─── 依赖：第 1 层 ─── 耗时：4h ─── 消除 ~30% 误检
    │
    ├─ 第 3 层 ─── 全目标追踪 ─── 依赖：无（可与 1/2 并行）── 耗时：2h ─── 消除 ~15% 误检
    │
    ├─ 第 4 层 ─── 场景先验 ─── 依赖：无 ─── 耗时：1h ─── 消除 ~5% 误检
    │
    └─ 第 5 层 ─── 模型重训 ─── 依赖：标注数据 ─── 耗时：3d ─── 源头优化
```

1-4 层总计约 1 天工作，预期综合消除 90%+ 误检，**不增加延迟，不掉帧，不降低真目标检出率**。

| 参数 | 当前值 | 建议值 | 说明 |

### 高度分层阈值

| 参数 | 当前值 | 建议值 | 说明 |
