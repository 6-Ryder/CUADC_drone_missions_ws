## 证据链: 算法为主

### 1. 同一算法同一分钟, 下降段稳定、悬停段失控 (最硬证据)

- 边伺服边下降 (5.6m→3.4m): px_err 持续 24-37px (:139-147) —— 环境不变, 算法工作正常。
- 悬停复查切换瞬间: `source=none → reason=reset` (:149), 之后进入 40s 振荡。
- 风不会在状态切换的瞬间"恰好打开"; 问题出现在状态机/锁存切换点。

### 2. 失锁后 20s 限幅振荡 = 闭环不稳定, 不是风扰

- 08:30:11-25: marker 世界坐标估计在 ±0.25m 盒子内来回摆 (:151-192)。
- 横向指令长期顶在 ±0.24 m/s 饱和 (cmd 的第二分量持续 -0.235~-0.242)。
- 稳态风只会产生可被积分掉的固定偏置; 20s 不收敛的极限环是目标关联跳变 + 低增益 + EMA 滞后的自激振荡特征。

### 3. 重试后同样环境下干净收敛 (排除风)

- 08:30:29 重置后重锁, 300px→25px 只用 9s (:206-229)。
- 风若为主因, 重捕获后应再次挣扎; 实际收敛干净, 变化的是锁存状态。

### 4. 可指认的算法机制

- **双标识关联切换**: 投放区检测到 2 个蓝标 (`DROP_MARKER: n=2`, :114)。像素锁跳变门 `precision_align_max_jump_diag_ratio=0.55` (≈440px 对角线) 大于两标间距 (2.4m 高度约 150-280px), `precision_align_target_world_gate=1.5m` 也区分不了 → 锁可在两标间自由切换, 单帧 ~200px 跳变 (:161-163)。
- **增益/速度上限过低**: `max_speed=0.25 / fine_max_speed=0.065 m/s` + `step_s 0.12-0.18s` 短脉冲低占空比 + EMA (alpha=0.55) → 失锁后重新对心极慢 (9s 磨 300px)。
- **重置逻辑缺陷**: 目标短暂丢失后"清除像素锁定、按画面中心重捕获", 把锁重新按到画面边缘目标上 (`pixel=(460,3)`, :206)。

- 假目标 conf=0.36 仍被伺服 —— 与风无关。

- 同日上午多架次在投放区/精校反复出问题 = 系统性问题, 非天气。

## 风力角色评估

风只可能是**诱因**: 悬停复查时若阵风把机推开 (复查瞬间初始偏移就 90px), 会触发上面的失锁-重锁链条; 低空小机姿态扰动会放大像素跳变。但不能作为主因:
- 解释不了下降段稳定 / 重试后干净收敛的对比;
- 解释不了 conf 塌缩追假目标;
- 解释不了 07:18 架次 all_candidates_rejected。

## 排除风力的验证手段 (待办)

1. 对比 PX4 ulog (姿态 / 水平速度 / GPS 速度) 与精校振荡时段的对应关系。
2. 统计全天 5 个架次同一时段行为一致性: 若像素漂移方向与当日风向一致且多架次同向, 风力权重才需上调。
3. 修复后复飞对比: 双标关联去重 / 失锁重置策略 / 降落 conf 门槛接线后, 同风况下精校是否稳定。
