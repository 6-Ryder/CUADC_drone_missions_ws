## 2. 剩余风险(未杜绝)

**低空 2.6–3.4m 检测在视觉源端彻底消失**(8/12 18:48、8/13 主力死因):

- 现象: vision 管线活着、FPS 正常, 但 marker 发布完全停止; 悬停回升后恢复。
- 定位: 检测消失发生在 **yolo → blue refine 源端**, 不是被 FSM 判定拒绝。
- 嫌疑根因: 下降 + 侧向伺服动态中运动模糊, refine 的 circularity(≥0.35)/blue_ratio(≥0.4) 门槛失败。
- 后果链: 检测消失 → 从未对心 → latch 不生效 → 停滞检测不触发(pixel=inf) → 原地重试 1 次 → `_takeover("target lost after retry")` → **HOLD 卡在投放区**。

## 3. 两条待选方案

### 方案 A — 伺服证据兜底(FSM 侧, 不盲投)

**思路**: 现在只跟踪下降全程的最佳**像素**误差; 改为(或增加)跟踪最佳**地面**误差。若伺服曾在下降中把地面误差收敛到 ≤ 阈值, 说明"伺服曾经满足对心"(有物理证据), 超时后即使当前丢失也执行投放。

- 依据(实测日志): 8/13 架次 3.46m 高度地面误差曾达 **0.30m**(已在投放精度内), 但检测随后消失 → 未投放。若阈值设 0.4m, 该架次会投放。
- 优点: 不盲投 — 投放依据是"曾经对心"的物理事实; 直接堵死剩余卡点; 改动集中在 `state_drop.py`。
- 缺点: 触及"不盲投"设计边界(需明确"曾经对心"即视为满足); 若丢检测时飞机恰好被风吹离投放区, 可能偏投。
- 改动要点: `_descend_best_pixel_error` 旁增加 `_descend_best_ground_error`(从 status.ground_error_m 跟踪); 超时兜底条件从"当前像素误差有限"放宽为"曾经地面误差 ≤ 0.4m"; 阈值参数化。

### 方案 B — 源端鲁棒性(视觉侧, 治本)

**思路**: 让低空动态中检测不再消失 — 下降段(高度 < 3m 或下降速度 > 0)放宽 refine 门槛, 或下降段直接采用 yolo 框。

- 子方案 B1: 下降段放宽 refine 门槛 — circularity 0.35→0.25, blue_ratio 0.4→0.3, 缓解运动模糊误杀。
- 子方案 B2: 下降段(altitude < 3m)跳过 refine 的蓝验证, 直接用 yolo 框 + conf 门槛。
- 优点: 治本 — 视觉一直有目标, 对心伺服全程有效, latch 自然生效。
- 缺点: 放宽验证 = 假目标风险上升(需警惕 8/8 假目标追错教训); B2 较激进, 推荐 B1 优先。
- 改动要点: `vision_pipeline.py` marker 路径加高度/速度分支; 参数化门槛。

## 4. 建议决策路径

1. **先把 `fix-quick-drop-servo`(096cdf5)部署到 Jetson**(同步代码 + colcon build), 实飞 2–3 架次。
2. 看新架次日志:
   - 若不再卡投放区 → 维持现状, 两方案都不上。
   - 若仍卡住, 看 `对心宽限期内保持投放许可` 与 `DESCEND: 精校目标丢失重试耗尽` 日志:
     - 有"宽限期内"日志但最终仍没投 → 说明对心后丢失超过 1.5s, 调大 `precision_align_release_latch_s`(1.5→3.0)先试。
     - 无对心痕迹(从未锁定/从未对心), 且 vision 侧 marker 发布在下降段停止 → **机制②再现 → 上方案 B1**(治本), 若 B1 仍不够再上 A。
3. 方案 A/B 的实施可再找我, 均在 jetson 05a6068 工作区基础上改。
